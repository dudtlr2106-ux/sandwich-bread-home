# 개발 상태 · 2026-09-10

## 진단과 검증

- 원래 오류는 앱의 `appliance.start` 파서 누락. 기존 `72fa5c7`에서 수정되었고 운영 API의 비존재 장치 요청으로 수정 반영을 확인했다.
- 요청 파서를 분리하고 오류 코드를 추가했다. 삼성 시작 명령을 보내기 전에 실제 capability 버전의 명령 정의를 서버에서 확인한다.
- Next.js + TypeScript 및 서버 전용 SmartThings 토큰 구조를 유지한다.
- 단위 회귀 테스트 5개 통과. 프로덕션 빌드와 TypeScript 검사 통과.
- 실제 Next API를 로컬 SmartThings fixture에 연결해 두 가전 명령 본문, 일반 조명 상태 조회, 잘못된 요청, 명령 정의 변경, upstream 오류를 검증했다.
- 브라우저에서 모의 세탁기·식기세척기 시작 후 작동 중 표시, 전체 끄기, 로그 조회를 확인했다. 실제 가전 시작은 수행하지 않았다.
- 운영 조회 당시 세탁기 Smart Control은 꺼짐, 식기세척기는 켜짐. 이 상태는 이후 바뀔 수 있다.

## 기능별 상태

| 기능 | 앱 상태 | 실제 연결에 필요한 작업 |
|---|---|---|
| 조명·콘센트 | 개별 및 전체 ON/OFF, 실제 상태 조회 | KOCOM 패킷과 LAN transport 확인 |
| 난방 | 현재·설정 온도, ON/OFF | 방별 주소·온도 값·단위 검증 |

| 삼성 세탁기·식기세척기 | 전용 시작 명령, 원격제어·중복 시작 검사 | 실제 기기 준비 후 동작 검증 |
| 엘리베이터 | KOCOM RS485 방식으로 결정, 서버 API와 요청 로그 | 호출 패킷·응답·주소·브리지 연결 확인 |
| 로그 | 명령/오류 조회, 서버 로그 출력 | 운영 영구 저장소 결정 (현재 메모리) |

## KOCOM 엘리베이터 다음 단계

호출 경로는 앱 → 서버 → SmartThings Edge Driver → RS485-LAN 브리지 → KOCOM 월패드 계통이다.
실제 호출 패킷이 확인되기 전에는 `/api/elevator`가 라이브 모드에서 501을 반환한다.
모의 모드의 성공은 실제 송신을 뜻하지 않는다.

필요한 자료:

1. 월패드 모델, RS485-LAN 브리지 모델과 연결 방식(TCP/UDP), 통신 속도·패리티.
2. 월패드에서 엘리베이터 호출 전후의 시간 표시가 있는 수신 캡처.
3. 반복 호출·대기 상태의 캡처 비교와 주소, 길이, 체크섬, ACK 식별.
4. `kocom_protocol.md`에 관찰 결과를 기록하고 검증 완료된 명령만 드라이버에 연결.

현재 드라이버에는 확정 패킷과 transport가 없다. 건물별 주소나 패킷을 추측해 구현하지 않는다.

## 재현

Node.js 24에서 `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm typecheck`, `pnpm build`.
빌드 후 `node tests/smartthings.integration.mjs`는 포트 3011에 테스트 앱을 띄우고 종료한다.
브라우저 모의 검증은 `IOT_MODE=mock`으로 `pnpm start` 후 수행한다.

## 전원 제어 및 접수/작동 구분 보완

- 사용자 보고: 휴대폰 SmartThings에서는 식기세척기 시작 가능, 공식 PC 웹에서는 불가.
- 운영 로그에는 시작 명령 HTTP 200 접수만 존재했으며 실제 시작 확인은 없었다.
- 세탁기·식기세척기의 main switch를 전원 켜기/끄기로 별도 표시한다.
- SmartThings 결과 배열에서 FAILED/알 수 없는 응답은 실패로 처리한다.
- 명령 후 상태를 최대 3회 조회한다. 접수 후 상태 미반영은 unconfirmed로 카드와 로그에 표시한다.
- 회귀 검사 6개, 빌드, 실제 Next API+SmartThings 모의 서버 통합 검사 통과.
- 실제 가전의 원격 전원/시작 동작은 사용자 현장 테스트가 필요하다.

## 2026-09-16 사용 편의와 상태 신뢰성 보완

- 장치·방 이름 검색, 브라우저에 저장되는 즐겨찾기, 필터 초기화.
- 마지막 목록 확인 시각과 선택형 1분 자동 갱신. 숨겨진 탭과 명령 처리 중에는 자동 조회하지 않는다.
- 조회 실패 시 이전 정보임을 표시하고 새로고침 성공 전 제어를 차단한다.
- 개별 SmartThings 장치 조회 실패는 해당 카드에 표시하며 다른 장치 조회를 유지한다.
- 전체 켜기/끄기는 조명·난방·콘센트만 대상으로 하며, 연결 대상이 없으면 비활성화한다.
- 일괄 명령 결과를 반영 확인·확인 대기·실패로 구분한다. 실제 연결 전 엘리베이터 버튼은 비활성화한다.
- 로그 검색과 오류/주의/일반 필터. 로그의 운영 영구 저장은 아직 구현하지 않았다.
- 단위 검사 9개, Next 빌드, 모의 SmartThings 통합 검사(개별 조회 실패 포함) 통과.
- 브라우저에서 즐겨찾기 재접속 유지, 검색/초기화, 모의 장치 10개 일괄 끄기, 로그 필터와 PC·모바일 화면을 확인했다.
- 운영 확인에서 SmartThings 401 인증 실패를 발견했다. 401/403은 한국어 안내로 표시하고, 조회 실패를 장치 없음으로 표시하지 않도록 수정했다. 실제 장치 조회 재개에는 서버 토큰 갱신이 필요하다.
